# 협업 규칙

모든 작업에 WBS 번호를 붙이고, 그 번호를 이슈·브랜치·커밋·PR까지 똑같이 씁니다. 번호 형식은 `대분류.중분류.작업`(예: `2.3.1`)이고 작업 하나는 하루에서 이틀 크기입니다.

## 작업 한 번의 흐름

1. 이슈를 만듭니다. 제목은 `[2.3.1] 현금흐름 분석 API 구현`이고 "WBS 작업" 템플릿을 씁니다. 이슈 하나에 담당자는 한 명입니다.
2. `develop`에서 브랜치를 땁니다.
   ```bash
   git switch develop
   git pull
   git switch -c feat/2.3.1-cashflow-api
   ```
3. 커밋하고 push한 뒤 팀 채널 `#커밋현황`에 커밋 메시지를 그대로 붙여 넣습니다.
4. `develop`으로 PR을 엽니다. 본문에 `Closes #이슈번호`를 꼭 넣어야 머지할 때 이슈가 닫히고 보드 상태가 Done으로 바뀝니다.
5. 리뷰어 한 명 이상이 승인하면 머지하고 `#머지현황`에 남깁니다.

## 브랜치

| 브랜치 | 용도 | 규칙 |
| --- | --- | --- |
| `main` | 배포 기준 | `develop`에서 PR로만 합칩니다 |
| `develop` | 개발 통합, 기본 브랜치 | 기능 브랜치에서 PR로만 합칩니다 |
| `feat/WBS번호-작업명` | 기능 개발 | 예: `feat/2.3.1-cashflow-api` |
| `fix/WBS번호-작업명` | 버그 수정 | 예: `fix/2.3.1-cashflow-sum` |
| `refactor/` `docs/` `chore/` | 구조 개선, 문서, 설정 | 예: `docs/1.2.1-tool-spec` |

작업명은 영어 소문자·숫자와 `-`만 씁니다. `main`과 `develop`에는 직접 push할 수 없고, 승인 1개와 CI(`pr-rules`) 통과가 있어야 머지됩니다.

## 커밋 메시지

첫 줄은 `[머리말]_WBS번호/요약`, 다음 줄부터 바뀐 내용을 `-`로 적습니다.

```
[Add]_2.3.1/CashflowApi
- 월별 수입·지출 집계 추가
- 거래내역이 없을 때 빈 결과 반환
```

| 머리말 | 언제 |
| --- | --- |
| `[Add]` | 기능, 파일 추가 |
| `[Fix]` | 버그 수정 |
| `[Refactor]` | 동작은 그대로 두고 구조 개선 |
| `[Docs]` | 문서, 주석 |

## PR

- PR 하나에는 이슈 하나만 담습니다. 너무 커지면 나눠서 올려 주세요.
- 제목은 이슈 제목과 같게 `[2.3.1] 현금흐름 분석 API 구현`으로 씁니다.
- 화면이 바뀌면 스크린샷을, API가 바뀌면 요청·응답 예시를, Agent가 바뀌면 "질문 → 호출된 Tool → 응답"을 붙입니다.
- AI가 만든 코드도 본인이 읽고 이해한 다음 올립니다. 리뷰어가 물어보면 설명할 수 있어야 합니다.

## 기획이 바뀔 때

1. "기획·설계 결정" 이슈를 엽니다.
2. 정해지면 [project-context.md](project-context.md)의 상태(✅/🟡/⬜)와 변경 이력을 고치고, 큰 결정은 [decisions/](decisions/)에 한 장 남깁니다.
3. 영향받는 요구사항·Tool 명세·API 문서를 같은 PR이나 바로 다음 PR에서 맞춥니다.

## 리뷰

| 바뀐 곳 | 리뷰어 |
| --- | --- |
| `FrontEnd` | FE (진성민, 탁유진) |
| `backend/` `ai/` `data/` | BE (이우진, 손수연, 최다인, 현준혁) 중 작성자 외 1명 |
| `infra/` `config-repo` `.github/workflows` | 클라우드 (곽호윤) |
| `docs/` 기획·요구사항 | PM (진성민) |

- 리뷰 요청을 받으면 그날 안에 봐 주세요.
- 꼭 고쳐야 하는 문제(버그, 보안, 빌드 실패, 금융 고지 누락)는 Request changes로, 취향 차이는 코멘트로만 남깁니다.

## 비밀 정보와 개인정보

API 키, DB 비밀번호, 클라우드 자격 증명은 절대 커밋하지 않습니다. `.env`로 관리하고 예시는 `.env.example`에 값 없이 남깁니다. 실수로 올렸다면 바로 팀장(손호성)과 클라우드 담당(곽호윤)에게 알리고 키를 폐기합니다. 실제 거래내역·계좌번호 같은 개인 금융 정보도 커밋하지 않습니다.
